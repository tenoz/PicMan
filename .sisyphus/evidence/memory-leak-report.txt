## 2. 发现的问题

### 问题 1: LRUCache 与文件移除不同步

**严重程度**: 🔴 高

**文件**: `App.tsx`

**问题描述**:
当用户移除文件时 (`handleRemoveFile`, `handleRemoveFiles`)，只释放了 `previewUrl`，
但 `processedBlobCache` (LRUCache) 中仍然保留已删除文件的 `processedBlob` 引用。
这导致即使文件从 UI 中移除，其处理后的 Blob 数据仍然被缓存占用内存。

**修复方案**:
1. 在 `handleRemoveFile` 中调用 `processedBlobCache.current.remove(id)`
2. 在 `handleRemoveFiles` 中批量调用 `remove()` 方法
3. 在 `handleClearAll` 中调用 `processedBlobCache.current.clear()`

**代码变更**:
```typescript
// 修复前
const handleRemoveFile = (id: string) => {
  setFiles(prev => {
    const target = prev.find(f => f.id === id);
    if (target) URL.revokeObjectURL(target.previewUrl);
    return prev.filter(f => f.id !== id);
  });
  // ...
};

// 修复后
const handleRemoveFile = (id: string) => {
  setFiles(prev => {
    const target = prev.find(f => f.id === id);
    if (target) {
      URL.revokeObjectURL(target.previewUrl);
      // 从 LRUCache 中删除并释放 processedBlob
      const processedBlob = processedBlobCache.current.remove(id);
      if (processedBlob) {
        console.log(`[Memory] 释放文件 ${id} 的 processedBlob`);
      }
    }
    return prev.filter(f => f.id !== id);
  });
  // ...
};
```

### 问题 2: TaskScheduler 定时器无清理机制

**严重程度**: 🟡 中

**文件**: `src/utils/taskScheduler.ts`

**问题描述**:
`waitForComplete` 方法中使用了 `setTimeout` 循环检查任务状态，但没有提供清理机制。
如果组件在任务完成前卸载，这个定时器会持续运行，导致内存泄漏。

**修复方案**:
1. 添加超时参数支持
2. 在任务完成或超时时清理 `timeoutId`
3. 检查 `isDestroyed` 标志避免在销毁后继续检查

**代码变更**:
```typescript
// 修复前
public async waitForComplete(): Promise<void> {
  return new Promise((resolve) => {
    const checkComplete = () => {
      const stats = this.getStats();
      if (stats.pending === 0 && stats.running === 0) {
        resolve();
      } else {
        setTimeout(checkComplete, 100);
      }
    };
    checkComplete();
  });
}

// 修复后
public async waitForComplete(timeout?: number): Promise<void> {
  return new Promise((resolve, reject) => {
    let timeoutId: number | undefined;
    
    const checkComplete = () => {
      const stats = this.getStats();
      if (stats.pending === 0 && stats.running === 0) {
        if (timeoutId) clearTimeout(timeoutId);
        resolve();
      } else if (!this.isDestroyed) {
        setTimeout(checkComplete, 100);
      }
    };
    
    if (timeout && timeout > 0) {
      timeoutId = window.setTimeout(() => {
        reject(new Error(`等待任务完成超时 (${timeout}ms)`));
      }, timeout);
    }
    
    checkComplete();
  });
}
```

### 问题 3: LRUCache 缺少手动删除方法

**严重程度**: 🟡 中

**文件**: `src/utils/lruCache.ts`

**问题描述**:
LRUCache 只提供了 `delete()` 方法，但调用它会触发 `onEvict` 回调。
在某些场景下（如主动清理已删除文件的缓存），我们不希望触发回调。

**修复方案**:
添加 `remove()` 方法，允许手动删除条目而不触发 `onEvict` 回调。

**代码变更**:
```typescript
/**
 * 手动删除特定键（不从 onEvict 回调）
 * 用于组件需要主动清理特定条目而不触发淘汰回调的场景
 *
 * @param key - 要删除的键
 * @returns 被删除的值，如果不存在返回 undefined
 */
remove(key: K): V | undefined {
  const entry = this.cache.get(key);
  if (entry === undefined) {
    return undefined;
  }

  this.cache.delete(key);
  this.memoryUsage -= entry.size;

  return entry.value;
}
```

## 4. 建议

### 4.1 监控建议

在生产环境中建议添加内存监控:

```typescript
// 定期输出内存使用情况
setInterval(() => {
  const stats = processedBlobCache.current.getStats();
  console.log('[Memory] Cache stats:', stats);
}, 30000);
```

### 4.2 进一步优化

1. **限制最大并发处理数量**: 防止一次性处理过多图片导致内存峰值过高
2. **ProcessedBlob 压缩存储**: 对于不活跃的文件，可以考虑压缩存储以节省内存
3. **定期强制 GC 提示**: 在处理大批量文件后，可以提示浏览器进行垃圾回收
