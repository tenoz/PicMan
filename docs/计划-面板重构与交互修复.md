# 第一部分：交互 Bug（先做，都是小改动，但直接影响信任）

六个问题里有三个是同一类病根：**状态判断的顺序写反了，或者用了从来没被更新的"假状态"**。
这也是 `AGENTS.md` 坑 2 记过的老毛病（v1.2.2 的三个死状态），改的时候顺手把同类检查一遍。

## B1 导入暂停无效

**现象**：导入中点「暂停」，进度照走。

**定位**：`src/App.tsx` 的 `handleFilesAdded`，阶段 2「并发读文件」那段：

```ts
await Promise.all(
  Array.from({ length: Math.min(CONCURRENCY, totalFiles) }, async () => {
    while (cursor < pending.length && !stopImportRef.current) {
      const item = pending[cursor++];
      await readOne(item);
    }
  })
);
```

**根因**：这个 while 只检查 `stopImportRef`，**完全没检查 `pauseImportRef`**。而暂停检查只写在阶段 1 之后、阶段 2 之前的那个 for 循环里（那里的循环此时已经跑完了），所以按暂停等于按在空气上。

**修复**：在 `readOne` 内部或 while 循环体开头插入暂停等待，与 `handleFilesAdded` 现有的暂停片段同构（`setInterval` 100ms 轮询 `pauseImportRef` / `stopImportRef`）。注意**暂停时不能让正在读的那个文件中断**，等它读完再挂起。

**验收**：导入 500 张，10% 时暂停 → 进度立刻停住，等 5 秒不动；点继续 → 从断点接着走。

## B2 导入停止后，文件又冒出来

**现象**：点停止，列表清空；过半分钟，已读的那批文件又出现在列表里。

**定位**：同上函数，结尾：

```ts
if (collectedFiles.length > 0) {
    await handleFilesAddedRef.current(collectedFiles, { keepProgress: true });
}
```

**根因**：这段**没有检查 `stopImportRef`**。用户点停止后，正在跑的 6 个并发 `readOne` 会把手上的文件读完（每个几十毫秒），`collectedFiles` 已经攒了一批，然后无条件调用 `handleFilesAdded` 把它们塞进列表——表现就是"后台还在导，过一会儿又冒出来"。

**修复**：
- 停止后不再调用 `handleFilesAdded`，改为记一条日志说明已丢弃多少张；
- 若产品上希望"停止时保留已读到的"，那就保留，但**必须在停止那一刻就把它们加进去并提示"已导入 N 张，剩余已丢弃"**，不能延迟到几分钟后。

**最终决定（2026-10-31 老大确认）**：**丢弃**。点停止即放弃这一批，已读到的也不进列表。

**验收**：导入 500 张，进度到 30% 点停止 → 列表保持空，之后 1 分钟内不再有任何文件出现。

## B3 处理暂停后，按钮不变「继续」

**现象**：处理中点「暂停」，按钮还是「暂停」，再点也恢复不了。

**定位**：两处，都在 `src/App.tsx`：

1. 按钮文案（顶部工具栏）：
```tsx
{isProcessing ? <Pause /> : <Play />}
<span>{isProcessing ? '暂停' : (isPaused ? '继续' : '全部处理')}</span>
```
2. 点击处理：
```ts
const toggleProcessing = () => {
  if (hookIsProcessing) { hookPause(); }
  else if (hookIsPaused) { hookResume(); }
  else { handleBatchProcess(); }
};
```

**根因**：`useProcessing.pause()` 只 `setIsPaused(true)`，**没有把 `isProcessing` 置 false**。所以暂停期间两者同时为 true。而上面两处判断都是 `isProcessing` 优先 → 永远走不到"继续"分支。

**修复**（不改 hook 语义，避免牵连进度条显示、按钮禁用等一堆依赖 `isProcessing` 的地方）：
- 按钮文案改成 `isPaused ? '继续' : (isProcessing ? '暂停' : '全部处理')`，图标同理；
- `toggleProcessing` 把 `hookIsPaused` 的判断提到最前面。

**验收**：处理中暂停 → 按钮变「继续」+ 播放图标；点一下 → 恢复处理，按钮变回「暂停」。

## B4 处理终止后，下次处理不从头开始

**现象**：终止后点「全部处理」，已经处理完的那些被跳过。

**定位**：`src/App.tsx` 的 `terminateProcessing`：

```ts
setFiles(prev => prev.map(f => {
  if (f.status === 'processing') {
    return { ...f, status: 'pending' as const, errorMessage: undefined };
  }
  return f;
}));
```

**根因**：只把 `processing` 重置成 `pending`，**`success` 一个都没动**。而 `handleBatchProcess` 里 `queueLength = targetFiles.filter(f => f.status !== 'success').length`，`success` 会被当成"已完成"跳过。

**修复**：终止时把所有非 idle 状态统一重置：
- `processing` / `success` / `error` → `pending`
- 同时清掉 `processedBlob`、`processedSize`、`processingTime`、`inflation`
- 从 `processedBlobCache` 里删掉对应 id（否则内存里还留着旧产物，白占 1.5GB 预算）
- `sessionBytesRef` / `batchDetailRef` 一并清空

**验收**：处理 100 张，完成 40 张时终止 → 列表里 100 张全部回到待处理、体积列显示原始体积；再点处理 → 100 张全部重新处理。

## B5 导出暂停后，按钮不变「继续」

**现象**：导出中点暂停，进度栏状态文字变成「导出已暂停」，但按钮图标不变。

**定位**：`src/App.tsx` 第 189 行附近：

```ts
const [isDownloadPaused, setIsDownloadPaused] = useState(false);
```

然后传给进度条：`paused={hookIsZipping ? hookIsZipPaused : isDownloadPaused}`

**根因**：`isDownloadPaused` 是**从来没被 `setIsDownloadPaused` 更新过的假状态**（全项目只有声明、没有 set 调用）。而 `useExport` 里明明有真的 `isDownloadPaused`，在 249 行被解构成了 `hookIsDownloadPaused`，但**解构完没用**。

**修复**：删掉 App 里的假 state，直接用 `hookIsDownloadPaused`；状态文字那行（`isDownloadPaused ? '导出已暂停' : '正在导出'`）一起改。

**验收**：导出中点暂停 → 状态文字变「导出已暂停」+ 按钮变播放图标；点一下 → 继续，图标变回暂停。

**定位**：`src/components/ProcessingBar.tsx` 第 114–130 行那个 `{(onTogglePause || onTerminate) && (...)}` 区块。

**验收**：任何一种任务进行中，进度条右侧只有文字信息，没有按钮；顶部按钮能完成暂停/继续/终止。

# 第二部分：设置面板重构

## 现状问题

`ConfigPanel.tsx` 一个平面列表摆了 7 组东西：格式、质量、JPEG 编码、PNG 重压、尺寸、旋转翻转、水印、EXIF、防膨胀、并发、文件名后缀、ZIP 引擎、ZIP 分组。全都同等重要地平铺，用户每次都要在视觉上跳过 6 组不相干的东西。

## 设计：四组折叠 + 顶部预设条

### 分组（老大 2026-10-31 定名）

| 分组 | 包含 | 默认状态 |
|---|---|---|
| **输出** | 格式、质量、JPEG 编码（内置/原生）、PNG 重压档位、文件名后缀、**防膨胀策略** | 常驻展开（不可收起） |
| **变换** | 尺寸模式+数值、保持比例、旋转、水平/垂直翻转 | 收起 |
| **标记** | 水印（开关/文本/位置/透明度）、EXIF 保留 | 收起 |
| **性能** | 并发数 | 收起 |

> 防膨胀放在「输出」而不是「标记」：它决定的是"要不要用处理结果替换原图"，属于输出决策，跟水印/EXIF 这种"往图上加东西"不是一类。
> 「性能」目前只有并发一个项，等以后加了缓存/内存上限之类也归这里。

每组标题右边显示**当前值的摘要**，收起时也能一眼看到，例如：

```
▸ 变换     原尺寸 · 无旋转
▸ 标记     无水印 · EXIF 保留
▸ 性能     并发 2
```

这样收起不会丢信息，是"折叠"而不是"隐藏"。

### 交互细节

- 点击标题行整行展开/收起，箭头旋转动画 150ms。
- 展开状态存 localStorage（key：`configPanelSections`），下次打开保持。
- **「输出」组不允许收起**（老大 2026-10-31 确认）：它是核心，每次都要用。
- 水印开启时，「附加」组自动展开一次并在标题上标一个点，避免用户找不到。

### 预设条（放在面板最顶部，格式选择之上）

一排横向胶囊：`画质优先` `均衡` `小体积` `网页优化` `高清存档` `+ 保存当前设置`

- 点击胶囊 → 立即应用该预设到 config，其他面板控件跟着变。
- 当前配置与某个预设完全一致时，该胶囊高亮。
- 最后一个「+」打开"存为预设"对话框：输入名字 → 存进 localStorage。

**内置预增设想**（现有只有「网页优化 WebP」「高清存档 PNG」，缺 JPEG 压缩档）：

| 名字 | 格式 | 质量 | 说明 |
|---|---|---|---|
| 画质优先 | JPG | 90% | 暗部渐变、细密纹理基本无损，体积约大 30% |
| 均衡 | JPG | 82% | 默认档，肉眼差异小 |
| 小体积 | JPG | 72% | 分享/预览用，细节有损 |

这三档正好对应用户"质量 > 大小 > 耗时"的排序。

### 自定义预设

- 存储：`localStorage.customPresets`，数组，每项是一个完整 `ProcessingConfig` + `id` + `name` + `createdAt`。
- 列表分区显示：`内置` / `我的`（我的带删除按钮，删除前确认）。
- 保存时若名字重复，自动加序号或提示覆盖。
- 预设应用只覆盖「处理相关字段」，不能覆盖 `outputBaseDir`、`exportMode` 这类环境相关配置（避免把某台机器的路径带到别的场景）。
- **支持「从现有预设复制一份再改」**（老大 2026-10-31 确认）：点任意预设的「另存为」，以它的全部参数为底，改完存成新预设。这样「以 90% 为底微调」不用每次从零调。

# 附：本次调研确认的事实

- `useProcessing.pause()` 只置 `isPaused=true`，不改 `isProcessing`（B3 根因）。
- `App.tsx` 的 `isDownloadPaused` 全项目无 `setIsDownloadPaused` 调用，是死状态；真状态在 `useExport` 里，解构名 `hookIsDownloadPaused`（B5 根因）。
- 导入阶段 2 的并发读盘循环只检查 `stopImportRef`，不检查 `pauseImportRef`（B1 根因）。
- 导入 `finally` 前无条件调用 `handleFilesAdded`，未检查 `stopImportRef`（B2 根因）。
- `terminateProcessing` 只重置 `processing` 状态，`success` 保留（B4 根因）。
- `ProcessingBar` 的暂停按钮渲染正确（`paused ? Play : Pause`），问题在传进去的 prop（B5）。
- 现有预设只有 2 个（WebP 网页优化 / PNG 高清存档），没有 JPEG 压缩档。
