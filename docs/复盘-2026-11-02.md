# 复盘：2026-10-31 ~ 11-02 这一波

> 三轮高强度迭代，从「打包不出文件」一路查到「导出改走磁盘」。
> 这份文档只留**下次还会踩的坑**和**可复用的判断**，过程不复述。

## 一句话

功能上补齐了「重命名 / 扁平化 / 产物写盘」三块，但**真正的收获是把「静默失败」这一整类问题从代码里挖了出来**——这一波有 5 个 bug 属于「界面说成功，实际啥也没干」。

## 做成了什么

| 主题 | 结果 |
|---|---|
| 批量重命名 | 前缀 / 后缀 / 查找替换 / 序号 / 纯序号，ZIP 与目录导出共用 |
| 导出布局 | 扁平化开关（只摊平最外层以内），撞名自动加序号 |
| JPEG 编码 | 直读原图交 Rust 编码，3000×2000 单张 712ms → **265ms** |
| 产物写盘 | 三步落地：处理即落盘 → 导出走 `copyFile`/硬链接 → 只剩第 3 步删 Blob |
| 打包引擎 | 本机压缩首次真正可用（此前恒失效）、原子写入、重名不覆盖、211MB 从 **98s → 约 3s** |
| 进度条 | 条纹 / 缓动 / 打包走不确定态 / 完成后保留（待做） |

## 踩的坑

**1. `path.tempDir` 在 Tauri v1 里不存在**（v2 才有）
`systemZip.canZipNatively()` 用它做探测 ⇒ 恒为 `false` ⇒ 「本机压缩」选项**上线后一次都没真跑过**。同一个月里 `rustPng` 已经因为这个坑死过一次。
→ **判断：碰原生能力前先全局搜 `tempDir`**，统一用 `nativeBridge.resolveWorkDir()`。

**2. `isSkipped` 一个字段背两种语义**
它同时表示「真动图」和「处理后反而变大被挡回」，但日志文案写死成「检测到动态图片」。4459 条日志把 `.jpg` 说成 GIF，把排查方向带偏了半小时。
→ **判断：一个布尔字段有两种成因时，日志必须能区分**，否则它比没有日志更坏。

**3. `prefers-reduced-motion` 吃掉了自己写的动效**
给进度条做了无障碍降级，结果本机开着「减弱动态效果」，降级把条纹和来回跑全关了，被当成 bug 报回来。
→ **判断：先确认自己的机器有没有开这个设置**；另外**功能性动效（进度、加载）不该降级**，装饰性的才降。

**4. `find -newermt` 在 macOS 的 BSD find 上无效**
它不报错，只静默返回空。我据此断言「磁盘上一个 zip 都没有」，从代码一路查到 Rust 落盘，白绕大半天。
→ **判断：判断「文件不存在」只认 `ls` / `stat`**；`find` 的时间过滤在 BSD 上要用 `-mmin`。

**5. 导出日志从来不落盘**
`persistLogs` 只在「批量处理完成」时调用，导出无论成功失败都不写文件。出问题时日志里一个字都查不到，只能靠猜。
→ **判断：凡是「事后要查」的操作，日志必须落盘**（耗时、路径、引擎、方式全写）。

**6. 成功是假的：`saveFile` 缺一句 `return`**
Tauri 环境判断 `dialog`/`fs` 不可用后只 `console.error`，继续往下落到 `saveAs()`，最后**无条件 `return { success: true }`**。而注释自己写着「WKWebView 会把 Blob 下载做成 Unknown 文件，绝不能 fallback」。
→ **判断：注释写了「绝不能」，代码就必须有对应的 return/throw**，否则注释是假的。

**7. 阈值制造的问题**
给「内置 JSZip 会不会 OOM」定的 300MB 安全线，顺手把 100-300MB 的包推进了「内置慢慢磨」的区间——211MB 打了 **98 秒**。
→ **判断：阈值要按最慢路径的吞吐定**（JSZip 实测约 2.2MB/s），不是按内存安全线定。

**8. 长文件名 + 结尾序号，肉眼分不出**
`xxx.zip` 和 `xxx_1.zip` 在 Finder 里看着一模一样，用户以为没导出，实际三个包都在。
→ **判断：写盘成功要主动报出文件名**，别指望用户去目录里找。

## 可复用的判断

1. **静默失败是最大的坑**。这一波 5 个 bug 都是「界面说成功、实际没干」：缺 return、缺 catch、日志不落盘、探测恒 false、假成功。**先让失败可见，再谈修复。**
2. **改之前先拿数据**。打包慢，加了耗时日志一次就定位到「内置 JSZip 98 秒」；不加油耗只能猜。
3. **同一类约束要查所有出口**。「绝不覆盖」这条，目录导出写了 `resolveFreePath`，ZIP 就漏了一整年。
4. **分步上线，每步可回退**。产物写盘分三步，前两步完全没改变现有行为，第三步才有风险。

## 遗留

- **第 3 步没做**：`processedBlob` 与 LRU 还在，内存仍按批次增长（当前双存）
- `App.tsx` 1753 行，通知栏 / Info Modal 仍是内联
- `GEMINI_API_KEY` 还留在 `vite.config.ts` 的 `define` 里（会内联进产物）
- 1.2.1 / 1.2.2 都没打过包，`releases/` 最新还是 1.2.0

# 第二批：功能收尾（11-02 白天到晚上）

> 六个提交，把「进度条完成态 / 导入双修 / 外观三态 / 提示条重做 / 产物不占内存」做完。
> 上面那份的遗留里，**「第 3 步没做」这条已经清掉了**。

## 做成了什么

| 主题 | 结果 |
|---|---|
| 进度条完成态 | 三条槽位跑完停在原地报结果（成功/跳过/失败/耗时），有失败转琥珀 |
| 导入 | 重复拖放不再误报「n 个文件未导入」；进度条不再来回伸缩 |
| 外观 | 跟随系统 / 始终亮 / 始终暗，首屏内联脚本防白闪 |
| 提示条 | 成功 5s 自消（悬停暂停）、警告常驻、最多 3 条、浮在顶栏上 |
| 内存 | **产物不再常驻，内存与批次大小脱钩**，整套 LRU 拆除 |

## 踩的坑

**1. 一个根因会连着冒好几个症状**
Tauri 把一次拖放投递了两次，先是「误报未导入」，两天后又是「进度条来回伸缩」，中间还夹着「每次白读一遍几百 MB」。
→ **判断：修完第一个症状先问一句「还有谁共用这个根因」**，别等它换个脸再来一次。

**2. `await processFiles()` 不是「干完了」**
它只是把任务丢给调度器就返回。测试拿它当同步点直接断言产物，机器一忙就 `undefined`——这就是那个「重跑就过」的 flaky，藏了至少两次。
→ **判断：时序断言一律轮询等条件成立**；另外**查 flaky 必须留全量日志**，`| tail -n` 截断等于把证据扔掉（这次就是靠完整日志才抓到）。

**3. 换存储介质时，「只认旧介质」的地方会静默失效**
产物从内存搬走后，单张下载第一行 `if (!file.processedBlob) return`、列表下载按钮 `canDownload` 只判 Blob、预览只读 Blob——三处全成了「点了没反应」。
→ **判断：换存储模型前，先 grep 一遍所有读取点列成清单**，再一个个改。这比边改边发现可靠得多。

**4. 两个 `bg-*` 同时挂在同一节点上，靠样式表顺序决胜**
进度条填充色写成了 `hasFailure ? 'bg-amber-400' : isDone ? 'bg-amber-400' : c.bar` 再叠一个 `bg-emerald-500`。
→ **判断：同一个属性只算一次，先得出一个变量再用**，别指望 CSS 优先级。

**5. Tailwind 类名不能运行时拼**
`bg-emerald-600` + `/80` 拼出来的类名，静态扫描看不到后半截，**整串失效**——底色和透明度一起丢。
→ **判断：含变体的类名（`/80`、`hover:`、`sm:`）必须在源码里整串出现**。

**6. JSX 属性位置不能写 `{/* */}`**
`<button {/* 注释 */} onClick={...}>` 是语法错误，我连犯两次。
→ 注释要么在 `return (` 之后的表达式位（`//` 可用），要么在 children 位（`{/* */}`）。

**7. 脚本按「第一个匹配」定位锚点会撞车**
批量补缩进时用 `} finally {` 当结束锚点，撞上了函数内部那个同名块，只改了一半。
→ **判断：锚点必须连上下文一起断言**（起点、终点、结束标记三处都 assert + 打印出来看）。

**8. `act` + `advanceTimersByTime` 一次推完不生效**
`setLeaving` 触发的 effect 要等 `act` 收尾才注册，中间那个 200ms 定时器还没建出来。必须分两段推进。

## 可复用的判断

5. **症状不同 ≠ 原因不同**。三周内同一个「Tauri 双路投递」换了三张脸出现，第二次就该去查根因而不是打补丁。
6. **改模型前先列清单**。存储、状态、接口的迁移，grep 出的调用点比记忆可靠。
7. **「不是我的锅」要用证据说话**。判断某个失败是否由本次改动引入，看两件事：改动的文件有没有进那条链路、新增测试是不是全是同步断言。
8. **功能性和装饰性动效分开**。进度条动效停了会被当成卡死，所以不响应 `prefers-reduced-motion`；提示条淡入淡出纯装饰，必须响应。上次是踩坑，这次是反过来用对。
